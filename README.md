# ESP32 Wi-Fi Thermometer v0.4.0

Полный проект для ESPHome 2026.7.x и ESP32-C3 Super Mini.

## Возможности

- DS18B20 на GPIO4;
- штатный ESPHome Web Server v3;
- OTA через Device Builder и веб-портал;
- отправка температуры в Народный мониторинг;
- кольцевой буфер 1000 температур в RAM;
- журнал 100 событий;
- кольцевой буфер 250 строк DEBUG-лога;
- отдельная страница `/history`;
- JSON endpoints:
  - `/history.json`;
  - `/events.json`;
  - `/logs.json`.

## Установка файлов

Скопируйте содержимое архива в:

```text
C:\Users\iven\esphome\
```

Структура:

```text
C:\Users\iven\esphome\
├── esp32-wifi-term.yaml
├── secrets.yaml
└── components\
    └── temperature_history\
        ├── __init__.py
        ├── temperature_history.h
        └── temperature_history.cpp
```

Файл `secrets.example.yaml` скопируйте под именем `secrets.yaml`.
Если `secrets.yaml` уже существует, перенесите в него только недостающие строки.

```

```

Используются логин и пароль из `web_server.auth`.

## Память

- 1000 точек × 30 секунд = 8 часов 20 минут температуры.
- 250 строк логов хранятся до перезагрузки.
- Длинные сообщения обрезаются до 220 байт.
- Никакие данные истории не пишутся во Flash, поэтому постоянного износа памяти нет.

Приблизительный расход RAM зависит от длины строк. Буфер температуры небольшой, но DEBUG-лог может занять десятки килобайт. Для ESP32-C3 это разумный компромисс. Не увеличивайте `max_log_lines` без необходимости.

## Почему штатный log очищался

Встроенная страница ESPHome показывает поток лога в браузере. После обновления страницы браузер открывает новое соединение и старые строки уже не получает. Новый компонент подписывается на logger внутри ESP32 и хранит последние строки в кольцевом буфере.

## Подключение DS18B20

```text
DS18B20       ESP32-C3 Super Mini
VCC           3.3V
GND           G
DATA          GPIO4
```

Резистор 4,7 кОм между DATA/GPIO4 и 3.3V.


## Исправления 0.3.1

- Исправлена компиляция под ESPHome 2026.7.3: `send()` теперь получает `const char *`.
- Используется новый метод `url_to()` вместо устаревающего `url()`.
- Добавлен штатный компонент `debug`:
  - свободная RAM;
  - минимальная свободная RAM с момента запуска;
  - максимальный непрерывный блок RAM;
  - фрагментация RAM;
  - максимальное время главного цикла;
  - частота CPU;
  - сведения о чипе, Flash и версии ESP-IDF;
  - причина последней перезагрузки.

### О загрузке процессора

ESPHome не предоставляет надёжный универсальный датчик «CPU load, %». Вместо выдуманного процента показаны частота CPU и максимальное время главного цикла. Рост `Loop Time` указывает, что устройство задерживается на обработке компонентов.

### О свободном месте во Flash

Flash ESP32 разделена на служебные и OTA-разделы, а не является обычным диском. Поэтому понятие общего «свободного места» неоднозначно. Текстовый датчик «Информация о плате» показывает физический размер Flash. Допустимый размер прошивки ESPHome проверяет при каждой сборке; точная занятость разделов печатается в логе компиляции.


## Исправление 0.3.2

ESPHome 2026.7.3 объявляет `url_to()` только в форме с переданным буфером.
Для совместимости с этой версией компонент снова использует `request->url()`.
Компилятор может показать предупреждение об устаревании, но это не мешает сборке.

## Изменения 0.4.0

- Температура публикуется после каждого измерения (`send_every: 1`), а не раз в три измерения.
- Удалена кнопка `PRESS`: штатная button-сущность ESPHome не умеет перенаправлять текущую вкладку браузера.
- На главной странице показан адрес `http://esp32-wifi-term.local/history`.
- `web_server.local: true` встраивает UI в прошивку для работы без интернета.
- Fallback AP включается через 30 секунд; captive portal использует gzip.
- Текстовый статус температуры теперь согласован с задержками warning/alarm.
- Наружу сейчас уходит температура в NarodMon раз в 5 минут; отдельные alarm-события в Zabbix/NarodMon ещё не отправляются.
